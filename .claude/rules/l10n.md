# Localization

- Every user-facing string comes from ARB. Files: `lib/core/l10n/arb/app_en.arb` (template) and
  `app_es.arb`. Config: `l10n.yaml`. Output (ignored by git): `lib/core/l10n/generated/`.
- Add each key to **both** files, then run `flutter gen-l10n`.
- Access in widgets: `import 'package:flutter_template/core/l10n/l10n.dart';` then
  `final l10n = context.l10n;` -> `l10n.signIn`.
- Placeholders need metadata in the template file:

```json
"homeWelcome": "Hello, {name}!",
"@homeWelcome": { "placeholders": { "name": {"type": "String"} } }
```

- Key names: `lowerCamelCase` with an area prefix (`login*`, `home*`, `settings*`, `error*`,
  `validation*`).
- Errors: `localizeError(error, l10n)` / `Failure.localize(l10n)`. Validators return an enum code;
  the page maps it to a key (see `LoginPage._emailError`).
- Do not hard-code strings in widgets, `Semantics`, tooltips or `SnackBar`s.
- Do not concatenate translated fragments; use one key with placeholders.
- Strings in tests may be literal English (the test locale resolves to `en`).
